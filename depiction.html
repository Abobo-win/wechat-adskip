微信小游戏去广告

跳过小游戏的激励视频广告 · 广告不播放 · 奖励直接到账

版本微信小游戏去广告 1.0.1
适用系统iOS 15.0 – 16.6.1（rootless 越狱）
依赖ellekit · preferenceloader
设置开关系统设置 → 小游戏去广告

它是怎么工作的

先说结论：微信把小游戏广告从原生层搬走了。

以前小游戏的激励视频走原生 SDK，所以 hook ObjC 的插件（老猫助手、GDDTHookByX、NoPublicAds……）都能拦。后来微信改成了：

运行时下载 https://lib/WAGameAd.js（约 1.58MB 纯 JS）
→ 在 JS 引擎里求值
→ 广告逻辑全在这个 JS 库里

这就是为什么所有传统去广告插件同时失效——不是插件坏了，是广告搬家了。

本插件的做法：hook JS 引擎的求值入口 JSContext2，在广告库执行之前改写源码字符串。

改哪里 dB() 里的免播卡检查
if(!FE.isWaGame||!y.videoSkipCard)return null;
改成什么 直接返回 {skipResult:"skip"}
为什么有效 调用方 uB() 里 if(o) return void e(o); 立刻短路
→ 广告根本不播，游戏直接收到 isEnded:true
安全性 只改内存字符串，不动磁盘文件，不触发微信的资源完整性校验

两个技术难点

难点 1：入口不是系统的 JSContext

是微信自编译 JavaScriptCore2 里的 JSContext2。主二进制里搜 createRewardedVideoAd 是 0 次。

难点 2：微信会运行时替换实现

实测日志：

已给实现打补丁 (第 1 个)  地址 = 0x1253c3c84
已给实现打补丁 (第 2 个)  地址 = 0x1168512c0   ← 微信换了

只打一次补丁会被静默绕过——广告照播，看不出哪里错了。本插件会跟随切换，但每个地址只打一次补丁（重复改方法表会导致竞态崩溃）。

设置开关

安装后去 系统设置 → 往下翻 → 「小游戏去广告」。

开关改动后需要重启微信才生效。

如果设置里找不到，respring（重启桌面）一次——PreferenceLoader 只在桌面启动时扫描。

已知限制

  • 如果某个小游戏的开奖由服务端校验，客户端补丁可能拿不到奖励
  • 微信以后改 WAGameAd.js 的结构会导致补丁失效——改一下正则即可
